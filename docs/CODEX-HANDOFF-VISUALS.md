Written 2026-11-07. Repo: `Streamentor/securitybusiness`, production branch `main` (Vercel deploys on merge). **Start from the latest `main`**: it has today's SEO pages (`/lovable-security-scanner`, `/guides/vibe-coding-security-checklist`), the expanded Supabase guide and a new floating mobile CTA (`src/components/MobileScanCta.tsx`). Read `AGENTS.md` first (this Next.js version has breaking changes; read `node_modules/next/dist/docs/` before using `next/image` or `next/og`).

## Why

Every page except the homepage is text, icons and cards. Visitors cannot see what they get before they scan, and long guides have nothing to break the reading. The goal is to show the product and explain the hard ideas visually, without hurting speed or honesty.

## The three kinds of visuals (pick the right one)

| Kind | Use for | Made with | Never use for |
|---|---|---|---|
| **A. Real product screenshots** | Showing the report, a finding, the repo loader, the rescan comparison | Playwright screenshots of the real app | Anything with invented numbers |
| **B. Code-native diagrams** | Flows, architecture, "outside vs inside", request paths, checklists | React + inline SVG components, Tailwind, theme colors | Photos or atmosphere |
| **C. Imagen illustrations** | Guide covers, one hero accent, abstract section art | Imagen | UI, text, logos, diagrams, people |

Rules that apply to all three:

1. **No fake product UI.** Product visuals must be real screenshots (A) or clearly labeled "Sample report" built from a real scan. Never render a fake score, fake finding count or fake customer.
2. **No text inside Imagen images.** Imagen garbles text. Any label goes in HTML or SVG on top.
3. **No third-party logos generated by AI.** Do not ask Imagen for GitHub, Supabase, Lovable, Vercel, Stripe or OpenAI logos. If a "works with" row is wanted later, use the official brand assets from each company's press/brand page, monochrome, small, and without implying endorsement. Not needed for this task.
4. **No security clichés.** No hoodies, skulls, binary rain, glowing padlocks on circuit boards, Matrix green.
5. **Real data only from apps Stefan owns.** Redact secret values, emails and private repo names if they appear. Our report already hides secret values; check anyway.
6. **Accessibility.** Every image gets a real `alt` describing what it shows (not "image of"). Decorative Imagen art uses `alt=""` and `aria-hidden`. Diagrams get a `<title>`/`aria-label` plus a visually hidden text summary.
7. **Dark theme only.** Match the site palette below. Nothing white-background.

## File layout and conventions (keep conflicts low)

Another scheduled job will edit page **copy** in the same files over the next two weeks. To avoid merge conflicts:

- Put every new visual in its own component under `src/components/visuals/` (one file per diagram, e.g. `ScanFlowDiagram.tsx`).
- In page files, add only a one-line usage (e.g. `<ScanFlowDiagram />`) at the anchor described below. Do not rewrite surrounding copy.
- Screenshots go in `public/images/product/`, Imagen art in `public/images/art/`, guide covers in `public/images/guides/<slug>.webp`.
- Use `next/image` with explicit `width`/`height`, `sizes`, and `priority` only for an above-the-fold image. Everything else lazy.
- Formats: WebP (or AVIF) at 2x the displayed size. Budgets: hero/above-fold image under 140 KB, other screenshots under 120 KB, guide covers under 90 KB.
- Shared wrappers to create first:
  - `src/components/visuals/BrowserFrame.tsx`: dark browser chrome (three dots, URL pill showing e.g. `scanmysaas.com/scan/…`), rounded 18 px, 1 px line border, soft `signal-shadow`. Children = image. Optional small top-right badge "Sample report".
  - `src/components/visuals/Figure.tsx`: `<figure>` with caption (13 px, muted), max width, consistent spacing (`mt-10`).

## B. Code-native diagrams to build

All are React + SVG, responsive (stack vertically under 640 px), use the tokens above, animate nothing by default (an optional subtle draw-in is fine if it respects `prefers-reduced-motion`).

- **D1 ScanFlowDiagram:** `Your URL` → `Crawl up to 25 pages` → `60+ checks (read-only requests)` → `Prioritized report with affected URLs` → `Fix prompt for Cursor / Claude / Codex` → `Rescan`. Five rounded nodes, lime connectors, small icon per node (lucide icons already in the project). Take the page count and check count from the page copy at build time (they are being fact-checked; if the copy changes, the diagram must match it, so pass them as props instead of hardcoding).
- **D2 OutsideInsideDiagram:** two columns. Left "Website scan sees" (TLS, headers, cookies, exposed files, source maps, CORS). Right "Repo scan sees" (committed secrets, Supabase RLS in migrations, GitHub Actions, public env vars, dependencies, AI review of routes). A center line labeled "your app". Cobalt for website, lime for repo.
- **D3 PrivateAccessDiagram:** `Your GitHub` → `ScanMySaaS GitHub App (contents: read, metadata: read)` → `One pinned commit` → `Up to 60 highest-risk files, in memory` → `Report`. A side note "Never clones, installs or runs your code". This matches `src/lib/github-app.ts` and `src/lib/github-scanner.ts`; keep it exactly to these facts.
- **D4 BoundaryMap:** five numbered zones matching the `boundaries` array on `/vibe-coding-security`: Secrets, Authorization, Data access, CI and releases, Public app. Draw: Browser → Public app edge → Server routes → Database, with GitHub/CI on the side. Number badges 1-5 map to the list below it.
- **D5 LovableStackDiagram:** Browser (React bundle containing the *publishable* key) → Supabase Data API → three tables: one with RLS (lime shield), one without RLS (red, "anyone with the publishable key can read it"), one with `using (true)` policy (amber). Side: Edge function box with "trusts user ID from body?" warning. Bottom: "Lovable ↔ GitHub sync" arrow to "Repo scan reads migrations". Use text labels, no logos.
- **D6 RlsRequestFlow** (Supabase guide): three request lanes (anon/publishable key, signed-in user A, secret/service-role key on server) hitting a table; show which rows each lane sees. Service-role lane labeled "bypasses RLS, server only".
- **D7 HeaderAnatomy** (security headers guide): a styled HTTP response block with `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`; each line has a short side annotation. Text must match what the guide says.
- **D8 CertTimeline** (SSL guide): horizontal timeline showing issue date, renewal window and expiry for an auto-renewing cert, with a red "expired" state. Only label durations the guide text states; do not add new dates.
- **D9 LeakTimeline** (secret scanning guide): `Commit` → `Push` → `Key is public in history` → `Rotate key` → `Purge history` → `Push protection on`, with "deleting the file is not enough" callout.
- **D10 PullRequestTargetDiagram** (GitHub Actions guide): fork PR → `pull_request_target` workflow with secrets and write token → checks out PR head → untrusted code runs with secrets. Safe version beside it: `pull_request`, read-only token.
- **D11 CrawlFlow** (robots/sitemap guide): Googlebot → robots.txt (allow/disallow) → sitemap.xml → page with canonical + noindex states.
- **D12 SeverityLadder** (reusable): Critical / High / Medium / Low with one-line meaning each, colors as above. Use on the free scanner page FAQ area or pricing.
